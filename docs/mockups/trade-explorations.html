Keep the builder fast.

Reuse cached roster/cap data to open the builder. Load Ideas and Inbox when opened; request weekly projections only when the visible analysis needs them. Selection feedback and cap previews remain local, with the existing debounced server check before Propose.

Use native layout and short CSS feedback. Keep projections and image requests out of repeated selection updates. Large future-season calculations stay outside the initial load.

Measured locally: about 120 KB per standalone prototype, eight local requests, zero external downloads. Selection reached the next browser frame in 15 ms or less. These mocks add no fonts, images, or chart libraries; production load times still need measurement during implementation.
